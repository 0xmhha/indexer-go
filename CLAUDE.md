# StableNet Blockchain Indexer (Go)

## Product Context

- **What**: Blockchain indexer framework for EVM chains, including StableNet (Stable-One) and Arc. Stable (USDT0-native, Tendermint/CometBFT) is outside the current scope (decision 10/13).
- **Target User**: StableNet dApp developers, block explorer backends
- **Core Value**: Block/transaction indexing with GraphQL, JSON-RPC and WebSocket APIs
- **Current Stage**: EVM framework refactoring complete; further validation and operational decisions remain (see current scope and remaining work in `docs/analysis/open-items.md`)
- **Dependencies**: `indexer-frontend` consumes this service's GraphQL API

## Technical Context

### Build & Run

```bash
make build          # build/indexer: generic EVM (version from git describe)
make build CHAIN=stablenet   # build/indexer-stablenet (CHAIN = a directory under x/)
make build-all      # indexer and every indexer-<chain>
make build-dev      # With debug symbols (CHAIN as for build)
make test           # Every test
make test-short     # Without the long tests (process kills, load)
make test-chain CHAIN=arc    # One chain's tests and its binary
make test-race      # Every test with the race detector (run before each commit and PR)
make coverage       # HTML coverage report
make lint           # golangci-lint
make docker-build   # Container image
```

CI (`.github/workflows/ci.yml`) runs gofmt, vet, `make lint` (and tools/astgraph), `go test ./...`, `scripts/test-postgres.sh` and `make test-examples` on every pull request and on the default branch. Jobs install the Go of go.mod's `toolchain` line (`GO_VERSION`, checked against go.mod) with `GOTOOLCHAIN=local`, so no job downloads a toolchain (Go 1.26.8, also used by golangci-lint and tools/astgraph). main requires the four jobs (lint, test, postgres, examples) to pass before a merge, administrators included. Tests wait for the state they check (`require.Eventually`, `waitSubscribed`, `waitRelayed`) instead of sleeping a fixed time; new concurrency tests are run with `-count=200`, `-race` and `GOMAXPROCS=1` before they are pushed. CI has no race job (decided 10/12: it would make CI too slow), so `make test-race` (`go test -race ./...`) must pass locally before every commit and pull request.

`scripts/test-postgres.sh` owns a uniquely named/labeled test volume and removes its container and volume on exit (including startup/test failures); failed volume cleanup is reported as failure. Its disposable PostgreSQL runs with `fsync=on`, matching capture/projection durability ACKs; never disable durability to make CI pass. Do not replace this with anonymous storage or broad volume pruning. External INDEXER_TEST_POSTGRES bypasses Docker ownership/cleanup.

`make generate` runs gqlgen, but the runtime GraphQL server does not use generated code.

### Key Patterns

- **EventBus**: `main.go` uses `events.NewEventBus` directly; subscriptions read `sub.Channel` (not `sub.Events()`)
  - Publishing is non-blocking; events are dropped when a buffer is full
  - Events of indexed blocks go through the outbox (R3-1): the writer records them in the block's transaction (`port.Outbox`, `/outbox/<seq>`; reorg events in the rollback's transactions via `port.UndoHook`) and `pkg/stream`'s relay delivers them after the commit in sequence order, waiting instead of dropping when the bus is full. Each event carries its chain's sequence (`events.Stream`, `events.SequenceOf`, 1, 2, ... without gaps); the bus drops sequences it has delivered (relay restarts deliver again from the last recorded cursor). Events are encoded with `events.MarshalEvent` (block events keep the header only). `eventbus.outbox: false` publishes directly after the commit, without sequences
  - Consumers of the change stream (R3-2) go through the bus port `stream.Bus` (`Join`, `Consume`); `stream.OutboxBus` reads the outbox directly, with one position per consumer group (`/meta/outbox/cursor/<group>`), so every group receives every event and resumes after the last batch it accepted. The relay consumes as `node.id` (default hostname); `Fetcher.Stream()` gives the bus to other consumers. Bus implementations must pass `pkg/stream/streamtest`
  - GraphQL subscriptions (`/graphql/ws`) go through the subscription engine `stream.Engine` (R3-3), the server's only bus subscription: copy-on-write subscription lists per event type, each event encoded once per subscription kind and shared, a bounded queue per connection (`eventbus.subscriber_buffer_size`). A connection whose queue overflows is disconnected with a `SLOW_SUBSCRIBER` error carrying `resumeFrom` (close 1008); "next" messages carry `extensions.sequence`. `api.subscription_engine: false` restores a bus subscription per client subscription
  - Resynchronization (R3-4): the subscription variable `fromSequence` delivers the events from that sequence still in the outbox, then live ones, each sequence once (`Conn.SubscribeFrom`; live events wait in the subscription while the outbox is read). Clients start from a snapshot: `{ streamSequence }`, then the state, then `fromSequence` = position + 1. Errors: `SEQUENCE_TOO_OLD` (pruned, `oldest`), `RESUME_UNSUPPORTED` (no outbox)
  - Notifications (R3-5) consume the change stream as group `notifications` (`NotificationService.SetStream`, wired in `streamNotifications`): each notification is stored under an id derived from the setting and the event's sequence before the batch is accepted, so a full queue or a restart loses none and redelivery creates none twice; the retry processor sends stored notifications the queue had no room for. Without the outbox the service subscribes to the event bus
  - `pkg/eventbus` (Redis, Kafka, factory with local degradation) exists but is not wired
- **Storage**: PebbleDB. Each block is indexed in one block transaction (`BeginBlock`, indexed batch bound to ctx; all access goes through `s.kv(ctx)`). Blocks are always read through the chain profile source; the legacy write path and go-ethereum client path were removed after v0.1.0 (`atomic_block: false` or `profile_source: false` is rejected at startup). Each block's commit records undo (`/undo/<height>`, last 128 blocks); on a reorg the live loop rolls back to the fork point, keeps the removed blocks as orphans (`/orphan/`, queryable with GraphQL `reorgs`/`orphanedBlock`/`orphanedTransaction`) and publishes a `reorg` event followed by the removed logs with `removed: true` (`docs/analysis/reorg-design.md`)
- Ancestor lookup (`source.BlockReader`, `Fetcher.BlockAt`): the RPC source reads a profile-verified full block without receipts; `source.Chained` preserves this optional path and other sources fall back to `BlockWithReceipts`. Normal ingest still reads and validates receipts. StableNet `EpochTracker` keeps at most 256 hash-keyed epoch resolutions, including verified ancestor paths, so repeated/speculative blocks reuse immutable header metadata across forks. Epoch blocks retain separate applied and next sets; a failed ancestor walk publishes no partial cache. WBFT primes the current block from the verified parent's resolution and reuses that parent for signing timestamps. This cache contains no account state and does not replace the writer's fresh canonical state check.
- **PostgreSQL** (`pkg/storage/postgres`, R4-2; `database.driver: postgres`, `database.postgres.dsn`/`schema`/`max_conns`; multi-chain mode uses schema `<schema>_<id>`; `pkg/app/store.go` is the only place that tells the drivers apart): relational adapter of the storage ports; tables keep query columns plus the model encoded with `pkg/core/model`; a block transaction is a PostgreSQL transaction bound to ctx, whose writes that return nothing read are queued and sent in one batch before its next other statement or its commit (`pending.go`; balances are read once per account per transaction, and balance.native prefetches a block's changed accounts in one query through the optional `port.BalancePrefetcher`); migrations under `migrations/` are applied on open (read-only stores only check the version). Every port passes the contracts (statistics computed from the ports live in `pkg/storage/history`, shared with Pebble). Rollback undo: tables a block only inserts into (blocks, transactions, receipts, logs, the address index, ERC-20/721 transfers, balance history; migration 0012) record in `undo_height` the height of the block transaction that wrote each row and are undone by deleting that height's rows (`undo_height_guard` refuses a block changing another height's rows); every other tracked table records its changed rows in `undo_log` by trigger, with the block's height (`indexer.height`, set by `SetHeight`), kept for the last 128 blocks, and `RollbackTo` replays them newest first; orphans and the outbox are not tracked. A migration that adds a table calls `undo_track` (or `undo_by_height_track`) for it (`TestEveryTableIsUndoTracked`, `docs/analysis/postgres-undo-design.md`); Tests need `INDEXER_TEST_POSTGRES` or run with `make test-postgres` (disposable container)
- **Roles** (`node.role`, R4-1, `pkg/app/role.go`): `all` (default) indexes and serves the API; `ingest` indexes and its HTTP server serves only health and metrics (`api.Config.HealthOnly`); `api` serves a PostgreSQL database another process indexes: opened read-only (it needs the schema migrated) except the notification keys (`postgres.Options.WritablePrefixes`), so it serves the notification API while the ingest process delivers and reloads settings every 5s; no fetcher, no verifier, and its event bus is fed by a relay over an `Ephemeral` `stream.OutboxBus` (positions in memory, nothing written, polled every `indexer.poll_interval`). Pebble allows only `all`/`ingest`; multi-chain mode only `all`
- **GraphQL schema** (R4-4): built from modules (`pkg/api/graphql/module.go`, one `schema_<module>.go` each; a field defined twice panics); chain-specific groups are extensions. `TestFrontendDocuments` validates indexer-frontend's GraphQL documents (`pkg/app/testdata/frontend/`, refresh with `-update`) against the served schema; `known-invalid.txt` lists the 26 that do not work (none broken by the refactoring); `docs/FRONTEND_MIGRATION.md` tells the frontend how to fix them and move polling to REST
- **API protections** (R4-3, `pkg/api/middleware`, `pkg/api/graphql/limits.go`): the client address is the connection's peer; `X-Forwarded-For`/`X-Real-IP` count only from `api.trusted_proxies` (read from the right). `api.rate_limit` is on by default (100/s, burst 200 per address). CORS never allows credentials (`*` answers `*`); WebSocket upgrades accept no Origin, allowed origins or the server's own host. GraphQL requests over `api.graphql.max_depth` (15) or `max_complexity` (5000; fields under a page count once per row) are refused before they run (`QUERY_TOO_DEEP`, `QUERY_TOO_COMPLEX`). The notification API (GraphQL notification fields, JSON-RPC `notification_*`) needs a key from `api.keys` (`middleware.APIKeyIdentify`; `UNAUTHENTICATED`, `-32001`; an unknown key is 401 on any path); settings belong to the key that created them (`NotificationSetting.Owner`, `notifications.ForCaller`: other keys' settings look absent, `notifications.operator_labels` see all, `max_settings_per_owner` quota); filters take `event` (a signature; matching logs carry `decoded` arguments) and `participants` (an indexed argument equals one of the addresses), parsed for both APIs by `notifications.FilterInput.Parse`; a setting's `delivery: fast` creates its notifications on the fast path: `fetch.BlockTap` (the notification service) gets each block's events in height order before the writer commits (`scheduler.go`, `sparse.go`), queued without blocking ingest (1,024 blocks, drops counted), ids keyed by transaction hash or block hash and log index, so re-evaluation creates none twice; the durable path skips fast settings except for reorgs; a setting of type `stream` is not stored: its notifications go to the owning key's WebSocket connections at `/v1/subscriptions/stream` (`notifications.Streams`, `pkg/api/subscription_stream.go`; at most `notifications.max_streams_per_owner` per key, a full connection is closed with 1008 `SLOW_SUBSCRIBER`), which also receive `lagging` when the fast path drops blocks; served only by a process that evaluates blocks (role `all`); in multichain mode every chain's App runs its own notification service over its own database, served under `/chains/{id}/` (graphql, rpc, `v1/subscriptions/stream`; `api.ChainNotifications`, JSON-RPC handlers hold their own service); a setting's optional CEL `condition` and `payload` (`pkg/notifications/expression.go`, cel-go) are type-checked and cost-estimated at registration over `event.<argument>` of the filter event, `log.*`, `tx.*`, `block.*`, `chain.id` (integers over 64 bits are strings compared with `bigCmp`); an evaluation error notifies nothing, is sent to the owner's stream as `error`, and ten in a row disable the setting; GraphQL `checkNotificationExpressions` and JSON-RPC `notification_checkExpressions` dry-run them over a sample log or transaction (`notifications.ExpressionCheck`); a setting's further `channels` (besides `type`, e.g. a webhook besides a stream; `pkg/notifications/channels.go`) get the same notifications, each stored copy under an id derived from the first channel's; with `notifications.webhook.verify_destinations` a webhook URL must echo a `url_verification` challenge when a setting is created or its URL changes (`pkg/notifications/webhook_verify.go`); webhook deliveries share a cap per host and Slack deliveries per URL (`notifications.destination_rate_limit`, default 10/s, burst 20; over it a delivery is deferred without counting an attempt); notification storage writes do not wait for an fsync (`storage.PebbleStorage.PutUnsynced`; the next synced commit makes them durable, and lost ones are recreated or redelivered); `filter.event` also requires the event's number of indexed topics; webhook and Slack deliveries refuse internal destinations at registration and at dial time and follow no redirects (`pkg/notifications/destination.go`, `notifications.allow_private_destinations` for development)
- **Operations guard** (`pkg/opsguard`, `operations` section; off when absent): the root App samples filesystem free space (30s), the PostgreSQL data directory size (5m, bounded du walk) and each raw window usage report. A stop threshold, a forecast reaching the floor/budget too soon (2h; raw 95% within 1h) or a missing observation writes `halt_file` (first cause kept) and ends `App.Run` with the `HaltError`. Startup refuses while the latch exists; only the `resume-check` command (3 samples 30s apart above `resume_free_bytes`, PGDATA below 80%) removes it, never for raw or integrity halts. `opsguard.Classify` maps window/capture errors to storage, capacity or integrity: the multichain `FailurePolicy` suppresses automatic restarts of classified failures, and storage/capacity latch and stop the whole process. Byte thresholds have no defaults. The Compose draft stops the indexer with SIGTERM/120s and PostgreSQL with SIGINT/60s (checked by preflight.py). An attached PostgreSQL store's `pg_database_size` and `pg_ls_waldir` sizes are journaled every `postgres_stats_interval` (60s) through the existing pool, never halting (`opsguard.AttachPostgresStats`; the latest attached chain store in multichain mode). Docker VM disk free space is checked only by `preflight.py` host checks before start/resume (a throwaway `df` container), not while running; `preflight.py --watch` (and `--start` after bringing the stack up, holding `watch.lock` first; `--background` detaches it) stops the indexer and then PostgreSQL (never down/rm) when the volume fails its checks, free space is <=110GiB or the latch carries `stopDatabase` (storage failures and PostgreSQL SQLSTATE 53100/58030, which Classify now maps to capacity/storage) (`docs/OPERATIONS_CAPACITY_DRAFT.md`)
- **RPC proxy** (`pkg/rpcproxy`, R4-5): every node call goes through `Proxy.load`: a cache hit is served without touching the node rate limit or circuit breaker, and concurrent misses for the same key share one node request (singleflight; a caller whose context ends stops waiting). Cache reads take the lock shared (CLOCK eviction); a node answering "not found" is not a circuit-breaker failure. `GetTokenBalances` reads the metadata of tokens the store lacks through the proxy (`Proxy.Call` caches eth_call answers, reverts included; `pkg/app/token_metadata.go`); metadata with an unanswered call is discarded, not stored
- **Ports** (`pkg/core/port`): ports speak the chain-neutral model (`pkg/core/model`: blocks, transactions, receipts, logs); go-ethereum `core/types` stays out of them (enforced by `TestPortsImportNoImplementation`) and is converted at the edges with `pkg/core/gethconv`. Consumers take the storage ports they use. The APIs take `port.QueryStore`, `feature.Deps.Storage` is a `port.Reader`, and optional ports (address index, token holder, module, orphan, ...) are taken by type assertion. Only `cmd` and `pkg/multichain` name `storage.Storage` or the Pebble types (`TestStorageAssemblyOnly`); `pkg/storage` declares no port aliases (`TestNoPortAliases`), and `pkg/core/port` imports no implementation (`TestPortsImportNoImplementation`)
- **RPC pool** (`pkg/rpcpool`): an `http.RoundTripper` under the go-ethereum RPC client, so ethclient, the block source and the recording proxy share it: per-attempt timeout (`rpc.timeout`), rate limit, failover to `rpc.fallback_endpoints` on connection errors, timeouts, 429 and 5xx (a failed endpoint cools down for 10s, then the primary is used again; JSON-RPC errors are returned as they are). `rpc.ws_endpoint` subscribes to newHeads to wake the live loop (live p95 head latency 1-2ms instead of ~50ms)
- Optional `indexer.acquisition_queue` (also a per-chain override) requires `state_prefetch` and separates continuous acquisition from ordered processing. A small `2*workers` window fetches blocks/receipts and prepares hash-bound initial balances/contract metadata; handoff releases its permits before commit. The processing queue defaults to 256 blocks and 256 MiB of serialized model + prepared payload, includes the active writer, and admits bytes in height order to avoid deadlock. It is an in-memory queue; restart discards speculative inputs and resumes from the committed cursor. Existing canonical checks, transactions, outbox, strict state failures and exceptional ordered resync/custom-handler RPC reads remain. `chunk_size` does not form a live acquisition barrier in this mode. The queue cannot raise RPC throughput or protect state already pruned before acquisition. Every 10s the chain logs target/acquired/committed heights, queue occupancy, payload, acquisition duration/interval, handoff/processing waits. Acquired height means contiguous preparation completed (speculative errors can still fail processing), not committed/canonical data. Acquisition interval includes backpressure and is distinct from a parallel job's duration. Queue polling respects `max(1s, poll_interval)` and shares observations; all calls retain the existing pool and cap.
- **Pagination** (`port.Page`): list ports take `Page{After, Limit, Offset}` and return the next page's cursor; a cursor page costs the same at any depth (Pebble `scanPage` over the list's key range), Offset is kept for clients that page by number. GraphQL `pagination.after` / `pageInfo.endCursor`, JSON-RPC `after` / `nextCursor`. GraphQL `transactions`/`logs` without a block range read the address index (newest first, `port.AddressTransactionsNewestFirst`, when `address.index` is active without a gap) or the log indexes; other filters read at most 10,000 blocks and report where they stopped in `scannedThrough`; a range over 10,000 blocks is cut to its newest (transactions) or oldest (logs) blocks and reported the same way
- **Fetcher**: The live loop, gap recovery and single-block fetches share one pipeline (`pkg/fetch/scheduler.go`): `indexer.workers` fetch concurrently, a reorder buffer indexes in height order, at most 2×workers heights are in flight (backpressure), and an error stops at the lowest failing height with every block below it indexed
  - Optional `indexer.state_prefetch` prepares initial native balances and token metadata outside the writer, using block hashes. `state_batch_size` (1; maximum 64, per-chain override) optionally groups same-hash balances and independent token properties; unusable envelopes fall back to individual reads, member/state/quota errors do not. HTTP request limits are not provider logical-call quotas. `state_workers` (4) shares read permits across a chain's preparation jobs; `state_max_bytes` (16 MiB) caps accounted retained payload per block, not the whole heap. Native preparation rechecks committed balance records after acquiring each shared read permit, skipping initialization completed while queued; a rollback restores the ordered writer read. The writer rechecks canonicality and record existence; resync/backfill/custom legacy handlers retain their ordered RPC path. SDK preparation APIs are additive. Preparation or explicit `indexer.pipeline_metrics` enables bounded stage latency/in-flight/payload measurements; default ingest incurs no new metric clocks/locks/sorting. RPC caps can make preparation slower; see work-log 3.12.
  - All state changes (index block, rollback, backfill) run as commands on one writer goroutine (`pkg/fetch/writer.go`, the only caller of `BeginBlock`, enforced by a test). Startup recovery is `Fetcher.Recover`: reorg check, feature state, backfill (order-independent features backfill online in the background)
- **Sources** (`pkg/source`): `rpc.endpoint: replay:///dir` replays an archive written with `rpc.record_dir`; `source.era_dir` reads the blocks held by era1 files (`gstable export-history`) from the files and later blocks from the node (the archive must match the node's chain). Era1 receipts carry consensus fields only; the chain profile derives the rest (`chains.BinaryProfile`, StableNet uses the Anzeon effective gas price rule). Blob gas prices are not derived from era1 (left nil): they depend on the chain's blob schedule, which block data does not carry
- **Profile selection**: The chain profile is selected once at startup: `--adapter` names a profile id or alias such as `stableone` that the binary links; empty, `auto` or the legacy `anvil` detects it from the node (`sourcerpc.Select`); any other name is a command-line error (`chains.Selectable`, also for `multichain.chains[].adapter_type`). A chain binary (`cli.WithChain`) refuses a node whose selected profile is not its chain; `indexer` refuses StableNet and Arc nodes (`cli.WithOtherProducts`), naming the binary to run. The former adapter layer (`pkg/adapters`, `pkg/types/chain`) was removed; token contracts that exist from genesis come from `chains.RegisterKnownToken`
- **Chain profiles** (`pkg/chains`, chain code under `x/<chain>`): decode raw blocks into the chain-neutral model; chain-specific behaviour reaches chain-neutral code only through registries: `pkg/chains` (profiles, aliases, accounting, fee delegation, native coin), storage keyspace (`storage.RegisterKeyspace`, used by reindex), GraphQL (`graphql.RegisterExtension`, `RegisterSubscription`), JSON-RPC (`jsonrpc.RegisterMethod`), event bus codecs (`events.RegisterCodec`) and known token metadata (`chains.RegisterKnownToken`). Chain packages store data through `port.KV` (bound to the block transaction by ctx) and each chain's bundle (`x/<chain>/bundle`) links them with blank imports into that chain's binary; startup work goes through `pkg/startup`. `pkg/chains/coupling_test.go` keeps chain-neutral packages free of profile imports and lets only `x/<chain>` code import `x/` (tests may; `pkg/app` tests link both bundles in `chains_test.go`, process tests build `pkg/app/testdata/indexer-all`); `TestChainIdentifierLimits` caps chain-specific names per package outside `x/` (`pkg/chains/testdata/chain-identifiers.txt`)
- **Head observations** (`pkg/fetch/head_observation.go`): live polls and explicit health start fresh RPCs; background progress and syncing block metrics share one recent successful observation (at most 1s) or an in-flight read. Raw head and finalized target are separate; errors invalidate observations and older issued requests cannot replace newer ones. Reused health observations retain their measured RPC latency. The optional `multichain.NodeHeightObserver` keeps legacy Indexer implementations working. Canonical hash/state reads remain uncached.
- **Features** (`pkg/feature`, `pkg/features/...`): optional per-block handlers that run inside the block transaction. Defaults come from the chain profile; override with `features.<name>.enabled` or `INDEXER_FEATURES=name,-name`. Features: `address.index`, `balance.native` (a `feature.StateReader`: the indexer starts only if the node keeps the state before the first block it will process, the next block or the start of its backfill, checked by `checkNodeState` in `pkg/app/node_state.go`; `features.balance.native.allow_pruned_state: true` starts accounts the node cannot give from 0 instead), `token.transfers`, `token.metadata` (asks the node whether a created contract is a token, as of its creation block; also a `feature.StateReader`, only `allow_pruned_state: true` permits reading the latest state instead), `aa.eip7702`, `aa.erc4337` (UserOperations of the known EntryPoints v0.6/v0.7 and those in `features.aa.erc4337.entry_points`, each with its version, per chain in multichain mode), `aa.erc7579` (on by default) `stablenet.wbft`, `stablenet.system_contracts`, `stablenet.fee_delegation` (on for StableNet), and `dex.pools`, `dex.trades` (off; R5-1, `pkg/features/dex`: Uniswap V3/V2 pools and pairs and perpetual order book markets registered only from the factories and engines in `features.dex.pools.venues`; trades with a 1e18-scaled price, `dexTrade` events; ### Configuration

Precedence (lowest to highest): defaults < YAML < environment variables < CLI flags

```yaml
rpc:
  endpoint: "http://127.0.0.1:8501"
  fallback_endpoints: []  # further HTTP(S) nodes of the same chain; calls fail over in order (pkg/rpcpool)
  rate_limit: 0           # requests per second to the nodes; 0 = unlimited
  ws_endpoint: ""         # newHeads subscription that wakes the live loop (polling stays the fallback)
indexer:
  workers: 100
  poll_interval: 50ms   # head polling once caught up (head latency); separate from error retry delay
  finality: head        # head | confirmations (with confirmations: N) | finalized; head suits StableNet (WBFT is final on insertion)
  orphan_retention: 1000 # reorganization records kept with their removed blocks; 0 keeps all
eventbus:
  publish_buffer_size: 65536    # events are dropped only when buffers are full
  subscriber_buffer_size: 16384 # per API subscription (per connection with the subscription engine)
api:
  port: 8080
  enable_graphql: true
  enable_jsonrpc: true
  enable_websocket: true
```

Pre-configured: `configs/config-{anvil,devnet,sepolia}.yaml`

Settings that are read but not wired (`eventbus.type` other than local, `node.priority`, `account_abstraction.entry_point_addresses`, replaced by `features.aa.erc4337.entry_points`) are reported at startup (`Config.UnsupportedSettings`), and so are `watchlist.enabled` and `resilience.enabled`, whose packages were removed after v0.1.0; `database.readonly: true` is rejected (an API process opens the database read-only with `node.role: api`). Command-line flags override the configuration only when given explicitly.
